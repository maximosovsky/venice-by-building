# Локальные фотографии: что сделано и почему так

Карточки показывали фотографии прямо с Викисклада. Это работало, но каждый показ зависел от чужого
сервера: своя задержка, свои ограничения по частоте (в этой работе Викисклад отвечал 429 и требовал
пауз по 40–50 секунд), и никакой возможности ускорить выдачу. Теперь фотографии лежат у нас.

## Что делает ступень s11

`pipeline/venice/s11_media.py`:

1. берёт из `web/data/wiki.json` все карточки с фотографией (1 082 записи);
2. скачивает исходную миниатюру Викисклада (960 точек по ширине) — ту же, что отдавалась в карточку;
3. уменьшает её до 560 точек по ширине и сохраняет в WebP, качество 76, в `web/media/<QID>.webp`;
4. пишет `web/media/manifest.json`: файл, размер, размер исходника, страница файла, автор, лицензия.

Повторный запуск не качает заново: готовые файлы пропускаются, поэтому шаг можно прерывать и запускать
снова. При 429 ступень ждёт и повторяет, при обрыве связи — тоже.

## Почему такая ширина и такой формат

| | было | стало |
|---|---|---|
| ширина | 960 точек | 560 точек |
| формат | JPEG (как отдал Викисклад) | WebP, качество 76 |
| средний вес | около 250 КБ | около 55 КБ |
| откуда берётся | thumb.wikimedia.org каждый раз | наш домен, `media/<QID>.webp` |

560 точек покрывают карточку с запасом на экранах с двойной плотностью: в доке фотография показывается
шириной около 300–340 точек. Формат WebP при том же виде даёт заметно меньший файл, чем JPEG, а
поддержка WebP есть во всех браузерах, которые тянут WebGL2, — то есть у всех, кому вообще доступна
эта карта.

## Атрибуция и лицензия

Уменьшение — производная работа, поэтому авторство и лицензия сохранены полностью:

- `web/data/wiki.json` в поле `image` хранит `page` (страница файла на Викискладе), `artist`,
  `license`, `licenseUrl`, а также `remote` — исходный адрес миниатюры;
- `image.thumb` теперь указывает на локальный файл, `image.local` равно `true`;
- в карточке подпись под фотографией осталась прежней: автор и лицензия со ссылкой на страницу файла;
- `web/media/manifest.json` дублирует авторство и лицензию по каждому файлу, чтобы провенанс не терялся
  при пересборке.

Изображения, у которых лицензия не допускала бы хранение у нас, в файл не попадают автоматически —
их нужно разбирать отдельно. Здесь таких не осталось: все 1 082 записи пришли с Викисклада, где
несвободных файлов нет по правилам самого проекта.

## Что качать в репозиторий, а что нет

Файлы фотографий попадают в Git вместе с `manifest.json`. Это одноразовая плата за независимость: при
каждом клоне репозиторий чуть тяжелее, зато карта грузит фотографии со своего домена и не зависит от
доступности Викисклада. Кэш отдаётся с `Cache-Control: public, max-age=604800` (правило в `vercel.json`).

Если нужен меньший вес репозитория, ширину можно опустить до 448 точек — это примерно на треть легче
(около 38 МБ против 60 МБ). Тогда ступень надо запустить заново после удаления `web/media` и манифеста.

## Как проверить

```bash
cd pipeline && python -m venice.s11_media centro     # скачать и сжать
python -m venice.s06_export centro                   # карточки получают локальные адреса
cd .. && python tests/test_viewer_contract.py        # 168 265 проверок
node tests/i18n_coverage.mjs                         # словари трёх языков
```
